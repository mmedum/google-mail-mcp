# Contributing

Thanks for looking. A few things here are not obvious.

## Before anything else

```
make hooks   # once: the pre-commit leak scan
make check
```

`make check` is the full gate set. `make parity` holds it against CI, so
a gate added to one is added to the other. `docs/development.md` says
what each gate holds and why.

## Rules that are not style

A change that breaks one of these is sent back:

1. **Nothing from a real mailbox enters the repository.** No address,
   subject, body, snippet, header, attachment name, label name or id,
   in code, docs, fixtures, tests, commit messages or pull requests.
   Fixtures are generated by `gmailtest`, never recorded. `make leaks`
   and the pre-commit hook enforce the shapes they can see.
2. **Stdout carries only MCP JSON-RPC frames.** Logs use `slog` to
   stderr. `forbidigo` enforces it outside `main`.
3. **Logs never carry the payload.** Method, tool, outcome, duration
   and a truncated id only. A test drives every tool with canaries.
4. **Mail content is data, never instructions.** It is rendered inside
   marked boundaries, and no tool description tells the model to act on
   what a message says.
5. **Sending and permanent deletion stay unregistered** unless their
   flags are set, and a send is never retried.

`CLAUDE.md` lists the rest, and `docs/architecture.md` explains them.

## Before you change the tool surface

Read `docs/architecture.md`. It holds the design, the decided
constraints, and an evidence log recording how each convention was
verified. Before adopting a convention, check it against the discovery
document or a live probe and add a row there.

The released tool surface is a contract. `make schema-diff` fails on a
renamed tool, a lost field or a new required input.

## Adding an API call

`make api-coverage` fails on a client call with no verdict. Add or update
the method's row in `testdata/api-coverage.tsv`.

## Errors

Every error is `[class] message`, from the closed list in
`docs/architecture.md` §6.5. `make classes` holds the code and the list
equal both ways, so change them in the same commit.

## Commits and branches

`main` takes pull requests only. Work on a short topic branch, write a
message that says what and why, and add a CHANGELOG line under
`[Unreleased]` for anything a user would notice. Tagging is the
maintainer's; `docs/release.md` describes it.

## Reporting a bug

Use the issue template. It asks for `doctor` output, the version and a
debug log, all safe to paste. Do not paste mail, a tool result or your
OAuth client JSON.
