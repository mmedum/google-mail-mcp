# Google Cloud setup

What a person must paste into the Cloud console. **This page is an input,
not a description**: the scope lists below are generated from
`internal/scopes`, and `scripts/gates staleness` fails when they differ.
A scope missing from your consent screen is not a stale document, it is
an `[auth]` from one tool weeks after a working setup.

## 1. Project and API

Create a Google Cloud project, then enable the **Gmail API** in it. A
missing API is the most common first-run failure, and
`google-mail-mcp doctor` names it.

## 2. OAuth consent screen

Every Gmail scope that can read a message is **restricted** — Google's
strictest class. What that means for you depends on the account:

- **In a Workspace organization**, choose **Internal**. Only accounts in
  your organization can sign in, and your administrator may need to
  allow the app.
- **Otherwise**, choose **External**, leave the app in **Testing**, and
  add yourself as a test user. In Testing, Google issues refresh tokens
  that **expire after seven days**, so you will run `login` again weekly.
  `docs/runbook.md` has the symptom. Publishing a personal app with
  restricted scopes needs Google's verification and a security
  assessment, which this server does not ask you to do.

Add the scopes for how you run the server:

| Mode | Set by | Scopes login requests |
|---|---|---|
| read-only | `GMAIL_READ_ONLY=true` | `https://www.googleapis.com/auth/gmail.readonly` |
| default | nothing (the default) | `https://www.googleapis.com/auth/gmail.modify` |
| send | `GMAIL_ENABLE_SEND=true` | `https://www.googleapis.com/auth/gmail.modify` |
| destructive | `GMAIL_ENABLE_DESTRUCTIVE=true` | `https://mail.google.com/` |
| settings | `GMAIL_ENABLE_SETTINGS=true` | `https://www.googleapis.com/auth/gmail.modify`, `https://www.googleapis.com/auth/gmail.settings.basic` |
<!-- scopes:end -->

### Why these and not others

**`gmail.modify`, not `gmail.compose` plus `gmail.labels`.** Trashing and
relabeling messages need `gmail.modify`, and `gmail.compose` sends mail
just as `gmail.modify` does — there is no scope that drafts without
sending. This server withholds sending by not registering the tool,
which is also what Google's own Gmail MCP server does.

**`https://mail.google.com/` only with `GMAIL_ENABLE_DESTRUCTIVE=true`.**
It is the only scope Google accepts for permanent deletion, and asking
for it by default would make that flag a label rather than a limit.

**`gmail.settings.basic` only with `GMAIL_ENABLE_SETTINGS=true`.** It is
the only scope Google accepts for writing a signature, a filter or the
vacation reply; not even `https://mail.google.com/` covers them. Add it
to the consent screen only if you turn the flag on. Forwarding,
delegation and send-as identities are never written, so
`gmail.settings.sharing` is never requested.

## 3. OAuth client

Create credentials of type **OAuth client ID**, application type
**Desktop app**, and download the JSON. A Web application client is
refused with a message saying so: the loopback redirect this server uses
is a native-app flow.

## 4. Sign in

```
google-mail-mcp login --client-secret ~/path/to/client_secret.json
google-mail-mcp doctor
```

`login` prints the scopes it is about to ask for before opening a
browser, and warns if Google grants fewer. Over SSH, add `--no-browser`;
the README's "Logging in over SSH" section has the port-forward line.
Changing `GMAIL_READ_ONLY` or `GMAIL_ENABLE_DESTRUCTIVE` changes the
scopes, so it needs `login` again; `doctor` says when.
